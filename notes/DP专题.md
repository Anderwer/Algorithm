# DP专题

## 前言

这份笔记用于整理常见的动态规划模型。  
写 DP 时，最重要的不是死记模板，而是先想清楚下面三件事：

1. **状态是什么**
2. **转移从哪里来**
3. **枚举顺序为什么这样写**

如果这三件事不清楚，代码就算写出来，也很容易错。

---

## 一、什么是 DP

动态规划本质上是在做一件事：

> 把一个大问题拆成若干个小问题，并且这些小问题会被反复使用。

所以，DP 题通常有两个特点：

- **最优子结构**：大问题的最优解可以由小问题的最优解推出
- **重复子问题**：同一个子问题会被多次用到

竞赛里常见的 DP 类型有：

- 线性 DP
- 背包 DP
- 区间 DP
- 树形 DP
- 状压 DP
- 数位 DP
- DAG 上 DP

这份笔记先整理最常见、最基础的几类。

---

## 二、写 DP 的通用步骤

### 1. 先定义状态

最常见的句式是：

- 设 `f[i]` 表示……
- 设 `f[i][j]` 表示……
- 设 `f[i][j][k]` 表示……

状态定义时要注意：

- 尽量让状态含义**单一、清楚**
- 尽量让状态足以推出答案
- 尽量让转移只依赖已经算过的状态

### 2. 再写转移

要问自己：

- 最后一步发生了什么？
- 当前状态可以从哪些旧状态转移过来？
- 这些来源是否会重复、遗漏？

### 3. 再想初始化

很多 DP 错，不是错在转移，而是错在初始化。

你要明确：

- 起点状态是什么
- 不合法状态要不要赋成 `-INF` / `INF`
- 有没有边界状态需要单独处理

### 4. 最后确定枚举顺序

枚举顺序不是随便写的，而是由“转移依赖关系”决定的。

比如：

- 如果 `f[i]` 依赖 `f[i - 1]`，通常正着枚举
- 如果 0-1 背包里 `f[j]` 依赖上一轮的 `f[j - w]`，就要倒着枚举
- 区间 DP 要先枚举区间长度

---

## 三、线性 DP

线性 DP 指的是：  
状态通常沿着数组、序列、字符串这类“线性结构”推进。

---

### 1. 最长上升子序列（LIS）

#### 问题

给定序列 `a[1..n]`，求最长严格上升子序列长度。

---

### 2. O(n^2) 做法

设：

- `f[i]` 表示**以 `a[i]` 结尾**的最长上升子序列长度

那么：

- 初始 `f[i] = 1`
- 枚举所有 `j < i`
- 如果 `a[j] < a[i]`，说明可以从 `j` 转移到 `i`

转移式：

$$
f[i] = \max(f[i], f[j] + 1), \quad j < i,\ a[j] < a[i]
$$

最后答案是：

$$
\max_{1 \le i \le n} f[i]
$$

#### 参考代码

```cpp
int LIS_n2(const vector<int>& a)
{
    int n = (int)a.size() - 1;
    vector<int> f(n + 1, 1);
    int ans = 0;

    for(int i = 1; i <= n; i++)
    {
        for(int j = 1; j < i; j++)
        {
            if(a[j] < a[i])
            {
                f[i] = max(f[i], f[j] + 1);
            }
        }
        ans = max(ans, f[i]);
    }
    return ans;
}
```

#### 这题最重要的理解点

很多同学第一次写 LIS，会把状态定义成：

- `f[i] = 前 i 个数的 LIS 长度`

这种定义不是不能做，但不好转移。  
更自然的定义是：

- `f[i] = 以 i 结尾`

因为“最后一个数是谁”一旦固定，前面的转移来源就清楚了。

这说明一个经验：

> 线性 DP 里，经常把状态定义成“以某个位置结尾”，这样更好转移。

---

### 3. O(n log n) 做法

设：

- `g[len]` 表示长度为 `len` 的上升子序列，其结尾最小能是多少

核心思想：

- 结尾越小，后面越容易接新数
- 所以我们总想让同长度子序列的结尾尽量小

处理每个 `a[i]` 时：

- 如果 `a[i]` 比当前最长序列的结尾还大，就扩展长度
- 否则，用 `a[i]` 去更新某个位置的最小结尾

#### 参考代码

```cpp
int LIS(const vector<int>& a)
{
    int n = (int)a.size() - 1;
    vector<int> g(n + 1, 0);
    int len = 0;

    for(int i = 1; i <= n; i++)
    {
        if(len == 0 || a[i] > g[len])
        {
            g[++len] = a[i];
        }
        else
        {
            int pos = lower_bound(g.begin() + 1, g.begin() + len + 1, a[i]) - g.begin();
            g[pos] = a[i];
        }
    }
    return len;
}
```

#### 为什么 `lower_bound` 是对的

因为我们要找的是：

- 第一个 `>= a[i]` 的位置

然后把它替换成更小或相等的值 `a[i]`，这样不会影响原本能达到的长度，反而让这个长度的结尾更优。

---

### 4. 其他变形

#### 最长不下降子序列（LNDS）

只需要把：

- `a[i] > g[len]`

改成：

- `a[i] >= g[len]`

并把：

- `lower_bound`

改成：

- `upper_bound`

---

#### 最长下降子序列（LDS）

把比较方向反过来即可。

---

#### 最长不上升子序列（LNIS）

同理，继续调整比较符号和二分方式即可。

## 四、背包 DP

背包 DP 是最经典的 DP 类型之一。

背包问题最核心的问题是：

- 当前物品能不能选
- 选几次
- 是否和同组物品冲突

---

### 1. 0-1 背包

#### 问题

每个物品只能选 **0 次或 1 次**。

设：

- `f[j]` 表示容量为 `j` 时的最大价值

转移式：

$$
f[j] = \max(f[j], f[j - w[i]] + v[i])
$$

#### 为什么要倒序枚举容量

因为 0-1 背包要求每个物品只能用一次。

如果你正序枚举，那么当前轮更新后的 `f[j - w[i]]` 又可能被本轮继续使用，相当于同一个物品被选多次了。

所以必须倒序。

#### 参考代码

```cpp
void zero_one_knapsack(int n, int m, vector<int>& w, vector<int>& v, vector<int>& f)
{
    f.assign(m + 1, 0);
    for(int i = 1; i <= n; i++)
    {
        for(int j = m; j >= w[i]; j--)
        {
            f[j] = max(f[j], f[j - w[i]] + v[i]);
        }
    }
}
```

---

### 2. 完全背包

#### 问题

每个物品可以选无限次。

转移式还是：

$$
f[j] = \max(f[j], f[j - w[i]] + v[i])
$$

但这次要**正序枚举容量**。

#### 为什么正序

因为完全背包允许当前物品选很多次。

正序时，本轮更新后的 `f[j - w[i]]` 可以继续用于本轮后面的状态，正好表示“继续再选一个当前物品”。

#### 参考代码

```cpp
void complete_knapsack(int n, int m, vector<int>& w, vector<int>& v, vector<int>& f)
{
    f.assign(m + 1, 0);
    for(int i = 1; i <= n; i++)
    {
        for(int j = w[i]; j <= m; j++)
        {
            f[j] = max(f[j], f[j - w[i]] + v[i]);
        }
    }
}
```

---

### 3. 多重背包

#### 问题

第 `i` 种物品最多选 `cnt[i]` 次。

这是介于 0-1 背包和完全背包之间的模型。

---

#### 做法一：二进制拆分

把 `cnt[i]` 拆成若干个 2 的幂之和：

例如 `13 = 1 + 4 + 8`

那么这一类物品就变成若干个“打包后的 0-1 物品”。

这是竞赛里最常用的做法，因为写法稳定。

#### 参考代码

```cpp
void multiple_knapsack_binary(int n, int m, vector<int>& w, vector<int>& v, vector<int>& cnt, vector<int>& f)
{
    f.assign(m + 1, 0);

    for(int i = 1; i <= n; i++)
    {
        int rest = cnt[i];
        for(int k = 1; k <= rest; k <<= 1)
        {
            int num = min(k, rest);
            rest -= num;
            int W = w[i] * num;
            int V = v[i] * num;
            for(int j = m; j >= W; j--)
            {
                f[j] = max(f[j], f[j - W] + V);
            }
        }
    }
}
```

---

#### 做法二：单调队列优化

当多重背包的数据范围很大时，可以用单调队列优化到 `O(nm)`。

这类写法更难，核心是按模 `w[i]` 分组，把转移式转成滑动窗口最值。

如果你还没熟练掌握基础背包，建议先把二进制拆分吃透，再去学单调队列优化。

---

### 4. 分组背包

#### 问题

物品被分成若干组，每组最多选一个。

设第 `g` 组中有若干物品。

转移时：

- 枚举这一组
- 枚举容量
- 枚举组内选哪个物品

#### 参考代码

```cpp
void group_knapsack(int groups, int m, vector<vector<pair<int, int>>>& items, vector<int>& f)
{
    f.assign(m + 1, 0);

    for(int i = 1; i <= groups; i++)
    {
        for(int j = m; j >= 0; j--)
        {
            for(auto [w, v] : items[i])
            {
                if(j >= w)
                {
                    f[j] = max(f[j], f[j - w] + v);
                }
            }
        }
    }
}
```

#### 这里为什么也倒序

因为同组最多只能选一个。  
倒序可以防止你在同一组里连续选多个物品。

## 五、区间 DP

区间 DP 的特征非常明显：

- 状态是一个区间
- 转移通常是枚举分界点
- 先算短区间，再算长区间

如果你看到题目有下面这种结构，就要警惕区间 DP：

- 合并区间
- 括号匹配
- 石子合并
- 回文划分
- 删除一段后左右区间合并

---

### 1. 区间 DP 的标准套路

通常写法是：

1. 枚举区间长度
2. 枚举区间左端点
3. 算出右端点
4. 枚举分界点转移

即：

- `len`
- `l`
- `r = l + len - 1`
- `k`

这是最标准的四层思路。

---

### 2. 石子合并

设：

- `f[l][r]` 表示把区间 `[l, r]` 合并成一堆的最小代价

那么最后一次合并，一定是把它拆成：

- `[l, k]`
- `[k + 1, r]`

所以转移式是：

$$
f[l][r] = \min_{l \le k < r}\left(f[l][k] + f[k+1][r] + sum(l,r)\right)
$$

其中 `sum(l,r)` 可以用前缀和快速求。

#### 参考代码

```cpp
int stone_merge_min(const vector<int>& a)
{
    int n = (int)a.size() - 1;
    vector<int> pre(n + 1, 0);
    for(int i = 1; i <= n; i++) pre[i] = pre[i - 1] + a[i];

    const int INF = 1e9;
    vector<vector<int>> f(n + 1, vector<int>(n + 1, INF));

    for(int i = 1; i <= n; i++) f[i][i] = 0;

    for(int len = 2; len <= n; len++)
    {
        for(int l = 1; l + len - 1 <= n; l++)
        {
            int r = l + len - 1;
            for(int k = l; k < r; k++)
            {
                f[l][r] = min(f[l][r], f[l][k] + f[k + 1][r] + pre[r] - pre[l - 1]);
            }
        }
    }
    return f[1][n];
}
```

---

### 3. 为什么区间 DP 要先枚举长度

因为：

- `f[l][r]` 依赖更短的区间
- 比如 `f[l][k]` 和 `f[k+1][r]`

所以必须先把短区间算出来，长区间才能转移。

这就是“按长度递增枚举”的根本原因。

## 六、DP 里最常见的错误

### 1. 状态定义不清楚

最典型的问题是：

- 你说不清 `f[i]` 到底表示什么
- 结果转移式和状态含义对不上

建议养成习惯：  
写代码前，先用一句中文把状态定义写清楚。

---

### 2. 初始化错误

例如：

- 最大值问题却把初值设成 `0`
- 最小值问题却没设 `INF`
- 忘了设置起点状态

这类错误特别常见。

---

### 3. 枚举顺序错

比如：

- 0-1 背包正着枚举
- 完全背包倒着枚举
- 区间 DP 没先枚举长度

这类错误的本质，是没有看清“当前状态依赖谁”。

---

### 4. 重复转移或漏转移

尤其在区间 DP 和构造型 DP 里特别常见。  
要养成习惯去问：

- 我这个转移是不是覆盖了所有情况？
- 会不会有某种情况被重复统计？

---

## 七、以后怎么判断一题是不是 DP

你可以从下面几个角度去判断。

### 1. 是否存在明显的“阶段”
例如：

- 枚举到第 `i` 个物品
- 处理到前 `i` 个数
- 处理某个区间 `[l, r]`

这说明很可能能定义 DP 状态。

### 2. 当前答案是否依赖更小规模答案
如果当前问题能从“更小”的问题推出，那就很像 DP。

### 3. 子问题是否会重复出现
如果会重复出现，那记忆化或 DP 就比暴力搜索更合适。

---

## 八、建议的练习顺序

如果你想系统学 DP，建议按这个顺序：

1. 线性 DP
   - LIS
   - 最大子段和
   - 简单字符串 DP

2. 背包 DP
   - 0-1 背包
   - 完全背包
   - 多重背包
   - 分组背包

3. 区间 DP
   - 石子合并
   - 括号类问题

4. 树形 DP / 状压 DP / 数位 DP
   - 这些再往后学

---

## 九、结语

DP 最难的地方，通常不是代码，而是：

- 你能不能找到合适的状态
- 你能不能解释清楚转移的来源
- 你能不能写出正确的枚举顺序

所以以后做 DP 题时，不要上来就套模板。  
先把下面三句话想明白：

1. **状态是什么**
2. **转移从哪里来**
3. **为什么这样枚举**

如果这三句话你都能说清楚，那么这道 DP 题大概率就已经做出来一半了。
