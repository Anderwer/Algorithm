# 延迟删除 multiset 与扫描型 DP

## 前言

这份笔记总结一个在比赛里很实用、但又经常不被单独提炼出来的技巧：

- **延迟删除 multiset**
- **扫描型 DP**

它们经常一起出现，尤其是在这种题目里：

- 下标从小到大扫描
- 每个位置会“产生一个未来一段时间有效的候选值”
- 当前点只需要知道“所有当前仍有效候选值中的最小值 / 最大值”
- 候选值会在未来某个时刻失效

这类问题如果硬上：

- 线段树
- 堆 + 真删除
- 每次暴力枚举可用状态

都可能写得很重。

而如果你能看出它是一个“**扫描线维护有效候选集**”的问题，就很容易转成：

- 一边扫描位置
- 一边往集合里加入未来有效候选
- 到失效时再删掉
- 当前答案直接取集合最值

这份笔记就是把这种思路单独讲清楚。

---

## 一、什么叫“扫描型 DP”

所谓扫描型 DP，指的是：

> 按某个顺序（通常是下标递增）处理状态，  
> 当前状态只依赖于“之前若干状态里当前仍有效的一部分”。

这类 DP 的典型形式是：

- 我们从 `i = 1` 扫到 `n`
- 某个旧状态 `j`
  - 只会对一段未来区间有贡献
  - 超过这段区间之后就失效
- 当前 `i` 想转移时，只需要看“所有对 `i` 仍有效的旧状态”的最优值

所以这类题的关键不是普通转移式本身，而是：

1. 一个旧状态什么时候加入候选集
2. 它什么时候失效
3. 当前如何快速取所有有效候选中的最值

---

## 二、什么叫“延迟删除 multiset”

先说结论：

> 当一个元素不是立刻删除，而是在未来某个时刻统一失效时，  
> 可以把“删除操作”延迟到那个时刻再做。

这就是“延迟删除”。

### 直观理解

假设你扫描到位置 `i`，你产生了一个候选值 `x`，它会在区间：

- `[i + 1, r]`

内都有效。

那你不用每次都问：

- “它现在该不该删？”
- “它还在不在？”

而是可以直接在产生它的时候记录一句：

- `x` 在 `r + 1` 的时候删除

也就是说：

- 现在先把它加入全局集合
- 到它真正该失效的时候，再把它删掉

这就叫延迟删除。

---

## 三、为什么 multiset 很适合做这件事

`multiset` 特别适合维护：

- 当前所有有效候选值
- 并且需要快速取最小值或最大值

因为它支持：

- 插入 `O(log n)`
- 删除一个指定值 `O(log n)`
- 取最小值：`begin()`
- 取最大值：`prev(end())`

所以只要你能把一个候选值的生命周期写成：

- 什么时候加入
- 什么时候删除

那就可以一边扫描一边维护。

---

## 四、这个技巧最常见的题型信号

以后你看到题目里有这些特征时，就要警觉：

### 1. 按下标从小到大扫描
例如：
- 扫描位置
- 扫描时间
- 扫描区间右端点
- 扫描事件顺序

### 2. 每个状态会产生一个“未来一段时间有效”的候选值
例如：
- 从位置 `i` 可以影响到 `[L_i, R_i]`
- 一个代价只在某个区间内合法
- 某个转移只对未来若干点可用

### 3. 当前只需要所有有效候选中的最小值 / 最大值
例如：
- `min`
- `max`
- 最小代价
- 最大收益

### 4. 一个候选值在未来某一刻之后统一失效
这就是最适合“延迟删除”的地方。

---

## 五、从 Round 980 B_Skipping 提炼出的核心模型

这题的核心结构非常适合拿来讲这个技巧。

### 原始状态的思路

设：

- `f[i]` 表示到达位置 `i` 的最小代价

在扫描到某个位置 `i` 时，如果当前状态 `f[i]` 有意义，那么它会产生一个新候选：

- `f[i] + a[i]`

并且这个候选值不是永久有效的，而是只在未来某一段区间内有效。

换句话说：

- 某个旧位置 `i` 会向未来贡献一个候选值
- 这个候选值只在一段范围内可用
- 超出范围后必须删除

于是当前状态的转移就变成：

> 当前点 `i` 的最优值 = 所有当前仍有效候选值的最小值

这就是标准的：

- 扫描型 DP
- 延迟删除 multiset

## 六、标准写法框架

这类题很常见的写法是下面这种：

```cpp
multiset<i64> st;
vector<vector<i64>> del(n + 2);

for(int i = 1; i <= n; i++)
{
    // 1. 当前点先用当前还有效的候选值转移
    if(!st.empty()) f[i] = min(f[i], *st.begin());

    // 2. 如果当前位置产生新候选, 先加入 multiset
    //    然后把“未来删除”记录在某个时刻
    if(这个候选值未来在 [i+1, r] 有效)
    {
        st.insert(val);
        del[r + 1].push_back(val);
    }

    // 3. 扫描到 i 结束后, 删除在 i+1 失效的元素
    for(auto x : del[i + 1])
    {
        st.erase(st.find(x));
    }
}
```

当然，具体是：

- 在循环开头删
- 还是循环结尾删

要看你状态定义和有效区间怎么对应。

但整体思想始终不变：

1. 候选值加入集合
2. 在未来某个时刻统一删除
3. 当前状态从集合最值转移

---

## 七、为什么不用优先队列，而常用 multiset

很多人第一反应会想：

- 既然只要最小值，那是不是堆就够了？

答案是：

- **不一定**

因为这里的难点在于：

- 候选值会在未来某个时刻失效
- 而堆不擅长删除任意指定值

当然，堆也可以用“懒删除”做，但如果题目里：

- 删除时机明确
- 删除对象值可直接记录
- 还可能有重复值

那 `multiset` 往往更省心。

### `multiset` 的优势
1. 可以删指定值
2. 重复值天然支持
3. 直接取最小值方便

---

## 八、这个技巧和“扫描线”的关系

其实这类题，从思想上说，不只是 DP，更像扫描线。

你可以这样理解：

- 每个旧状态产生一个“区间有效的候选值”
- 你在位置轴上从左往右扫
- 扫到某个位置时，维护当前所有还覆盖这个位置的候选值
- 当前答案就从这些候选值里取最优

这和很多扫描线问题的本质是一样的，只不过这里维护的是：

- DP 候选转移值

而不是：

- 几何对象
- 区间覆盖数量
- 某种事件集合

所以这个技巧其实可以看成：

> **扫描线思想在 DP 里的应用。**

---

## 九、延迟删除的两种常见写法

### 写法 1：按“失效时间”开桶
这就是最常见、最清楚的写法。

```cpp
vector<vector<i64>> del(n + 2);

st.insert(val);
del[expire].push_back(val);
```

扫描到 `expire` 时：

```cpp
for(auto x : del[expire])
{
    st.erase(st.find(x));
}
```

#### 适用场景
- 失效时刻是离散的
- 失效时间范围不大
- 扫描顺序明确

这是最推荐掌握的版本。

---

### 写法 2：堆懒删除
有时候你也会见到：

- 一个主堆
- 一个删除堆

每次取堆顶前，先把两个堆顶相同的元素一起弹掉。

这种写法适合：

- 只需要堆顶
- 删除对象不方便在固定时刻统一删
- 不想用 `multiset`

不过就比赛实战来说，如果能用 `multiset + 失效桶`，通常更直接。

## 十、这个技巧的真正关键，不是容器，而是“候选值生命周期”

你以后做这类题时，最重要的一步不是先想：

- 用堆
- 用平衡树
- 用线段树

而是先想清楚：

### 一个候选值的生命周期是什么？
也就是：

1. 它在什么位置产生？
2. 它从什么时候开始有效？
3. 它在哪个位置之后失效？

只要这三件事想清楚了，后面才好决定数据结构。

---

## 十一、这类题为什么容易写错

### 1. 搞错“什么时候删”
这是最高频错误。

比如某个候选值在：

- `[L, R]`

有效

那你要特别清楚：

- 是扫描到 `R` 后删
- 还是扫描到 `R + 1` 时删

边界一旦写错，答案就会整体偏掉。

---

### 2. 删除时直接 `erase(value)`
如果集合里有重复值，直接：

```cpp
st.erase(value);
```

会把所有这个值删掉。

正确写法通常是：

```cpp
st.erase(st.find(value));
```

只删掉一个。

---

### 3. 当前状态更新和加入新候选的顺序写反
有些题要求：

- 当前点不能用自己产生的候选值
- 有些题又允许

所以一定要想清楚：

- 是先转移
- 还是先加入候选

这个顺序是状态定义的一部分。

---

### 4. 失效桶下标开错
例如应该开到：

- `n + 2`

否则处理 `r + 1` 时可能越界。

---

## 十二、什么时候它比线段树更好

这类题有时也能用线段树做，但 `multiset + 延迟删除` 的优势在于：

- 写法轻
- 逻辑直接
- 常数小
- 很适合扫描型问题

尤其当题目本身就具有：

- “产生一个区间有效候选值”
- “当前只取全局最值”

这种结构时，用 `multiset` 往往比上线段树更自然。

---

## 十三、什么时候它不够用

如果题目要求的不只是：

- 全局最小值 / 最大值

而是：

- 区间最值
- 按值域复杂统计
- 需要合并左右子结构
- 还要支持复杂修改

那 `multiset + 延迟删除` 就不一定够用了。

这时候你可能需要：

- 线段树
- 树状数组
- 堆 + 哈希懒删
- 平衡树 + 更复杂信息

所以这个技巧的适用范围其实非常明确：

> **扫描过程中维护“当前有效候选集的最值”**

---

## 十四、把这个技巧抽象成一个通用模板思路

以后如果你再遇到类似题，可以按这个模板去想：

### 第一步：定义状态
例如：

- `f[i]` 表示到达 `i` 的最优值

### 第二步：找候选转移
通常会发现：
- 某个旧状态 `j` 会对未来一段区间贡献一个转移值 `val(j)`

### 第三步：把这个候选转移看成一个“带有效期的物品”
它的属性是：

- 产生时间
- 生效区间
- 失效时间
- 值

### 第四步：扫描维护当前有效候选的最值
这时就可以用：

- `multiset`
- 延迟删除桶

去维护。

---

## 十五、和普通 DP 最大的不同

普通 DP 很多时候是：

- 从固定几个前驱转移

而这一类扫描型 DP 的特点是：

- 当前状态的前驱不是固定的几个
- 而是“当前所有仍有效的旧状态候选”

所以它更像：

- 维护一个动态候选池

而不是传统意义上写一个简单转移式。

这也是为什么很多人第一次看到这类题，会感觉它“不像 DP”，其实它本质上还是 DP，只不过：

- 转移来源是一个动态集合

---

## 十六、小结

这份笔记想让你真正记住的，不是某一题的代码，而是下面这条思维链：

1. **按顺序扫描**
2. **旧状态会产生一个对未来一段区间有效的候选值**
3. **当前状态只需要所有当前仍有效候选中的最优值**
4. **用 multiset 维护当前最值**
5. **用“延迟删除”处理候选值失效**

把这五步串起来，你以后就会对这类题非常敏感。

---

## 十七、最后一句话

如果你看到一道题满足下面三句话：

- 从左到右扫描
- 每个旧状态只对未来某段区间有效
- 当前只要所有有效候选中的最值

那就应该立刻想到：

> **延迟删除 multiset + 扫描型 DP**
