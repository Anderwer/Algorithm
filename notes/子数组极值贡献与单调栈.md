# 子数组极值贡献与单调栈

## 前言

这份笔记是从 `Educational Codeforces Round 188` 的 `F. Sum of Fractions` 抽出来的。  
那道题最值得沉淀的，不是它具体的分数形式，而是它背后的这条非常高频的思维链：

1. 先研究单个对象的操作收益；
2. 再比较多个对象的边际收益；
3. 发现最优决策只和某个极值元素有关；
4. 把原问题转成 **子数组最小值 / 最大值贡献统计**；
5. 用 **单调栈** 计算每个位置作为极值时能负责多少个子数组；
6. 最后按题意再做进一步统计、离线或前缀处理。

如果你能把这一条链真正吃透，那么以后很多“看起来很综合”的题，你都能迅速拆开。

---

## 一、什么叫“子数组极值贡献”

先说最核心的一句话：

> 如果一个子数组的答案，只和它的最小值或最大值有关，那么就应该立刻想到“按极值统计贡献”。

这是竞赛里很高频的套路。

### 一个最经典的问题

给定数组 `a[1..n]`，求：

- 所有子数组最小值之和
- 或所有子数组最大值之和

这种题如果你逐个子数组去算，复杂度会非常大。  
但如果你换一个角度：

- 不去想“每个子数组的最小值是谁”
- 而去想“每个位置 `i` 作为最小值时，能贡献多少个子数组”

问题一下就变简单了。

---

## 二、为什么“按位置贡献”比“按子数组枚举”更自然

很多同学第一次做这类题时，思路是：

- 枚举左端点
- 枚举右端点
- 找最小值

这样想很自然，但复杂度通常不行。

更好的角度是：

### 对某个位置 `i`
问：

- 有多少个子数组把 `a[i]` 当作最小值？
- 或把 `a[i]` 当作最大值？

如果这个数量能算出来，那么：

- `a[i] * 这个数量`

就是它对总答案的贡献。

所以：

### 总答案
可以写成：

$$
\sum a_i \times (\text{位置 } i \text{ 作为极值时的贡献次数})
$$

这就把“按区间统计”转成了“按位置统计”。

---

## 三、单调栈为什么会出现

现在问题已经变成：

> 对每个位置 `i`，它作为子数组最小值（或最大值）时，能负责多少个子数组？

这个问题最标准的工具就是：

- **单调栈**

因为你需要知道：

- 往左最远能扩到哪里
- 往右最远能扩到哪里
- 并且一旦扩过头，`a[i]` 就不再是最小值 / 最大值了

这就是边界问题，而单调栈正是用来找“最近更小 / 更大元素”的。

---

## 四、最经典的公式

假设我们在统计“位置 `i` 作为子数组最小值的贡献”。

设：

- `L[i]`：左边第一个 **严格更小** 或 **更小等于** 的位置
- `R[i]`：右边第一个 **严格更小** 或 **更小等于** 的位置

那位置 `i` 能负责的子数组数量通常写成：

$$
(i - L[i]) \times (R[i] - i)
$$

### 这个式子怎么理解

不要死记，理解它更重要。

#### 左边有多少种起点选法
如果左边第一个阻止它继续当最小值的位置是 `L[i]`，  
那么子数组左端点可以选在：

- `L[i] + 1`
- `L[i] + 2`
- ...
- `i`

一共有：

$$
i - L[i]
$$

种。

#### 右边有多少种终点选法
同理，右端点可以选在：

- `i`
- `i + 1`
- ...
- `R[i] - 1`

一共有：

$$
R[i] - i
$$

种。

#### 两边独立
所以总数就是：

$$
(i - L[i]) \times (R[i] - i)
$$

这就是整个公式的来源。

---

## 五、最容易错的地方：严格和非严格怎么取

这是单调栈统计极值贡献时最容易出错的地方。

因为如果数组里有相同元素，例如：

- `2 2 2`

那么你必须决定：

- 这些相等的值到底由谁来负责？
- 左边那个？
- 右边那个？
- 还是会不会重复统计？

### 原则
你必须保证：

> 每个子数组只被一个位置负责。

所以常见做法是：

### 统计最小值时的常见一组写法
- 左边找第一个 **严格小于**
- 右边找第一个 **小于等于**

或者反过来也行：

- 左边找第一个 **小于等于**
- 右边找第一个 **严格小于**

只要你一边严格、一边非严格，就可以避免重复。

### 为什么要这样
因为对于相等元素：

- 如果左右都用严格
  - 可能会漏
- 如果左右都用非严格
  - 可能会重

所以最稳的经验就是：

> 一边严格，一边非严格。

---

## 六、统计“最小值贡献”的标准写法

这里给一个最常用的版本：

- 左边找第一个 **严格更小**
- 右边找第一个 **小于等于**

对应地：

- 左边单调栈通常弹 `>`
- 右边单调栈通常弹 `>=`

当然也可以反过来，只要逻辑统一即可。

### 参考模板

    #include <bits/stdc++.h>
    using i64 = long long;
    using namespace std;

    i64 sumOfSubarrayMin(vector<int>& a)
    {
        int n = (int)a.size() - 1;
        vector<int> L(n + 1), R(n + 1), st;

        // 左边第一个严格更小
        for(int i = 1; i <= n; i++)
        {
            while(!st.empty() && a[st.back()] > a[i]) st.pop_back();
            L[i] = st.empty() ? 0 : st.back();
            st.push_back(i);
        }

        st.clear();

        // 右边第一个小于等于
        for(int i = n; i >= 1; i--)
        {
            while(!st.empty() && a[st.back()] >= a[i]) st.pop_back();
            R[i] = st.empty() ? n + 1 : st.back();
            st.push_back(i);
        }

        i64 ans = 0;
        for(int i = 1; i <= n; i++)
        {
            ans += 1LL * a[i] * (i - L[i]) * (R[i] - i);
        }
        return ans;
    }

---

## 七、统计“最大值贡献”怎么改

完全同理。

如果是“位置 `i` 作为子数组最大值”：

- 把“小于”改成“大于”
- 把“更小”改成“更大”

例如常见的一组写法可以是：

- 左边找第一个 **严格更大**
- 右边找第一个 **大于等于**

模板只需要把比较号改掉即可。

### 参考模板

    i64 sumOfSubarrayMax(vector<int>& a)
    {
        int n = (int)a.size() - 1;
        vector<int> L(n + 1), R(n + 1), st;

        // 左边第一个严格更大
        for(int i = 1; i <= n; i++)
        {
            while(!st.empty() && a[st.back()] < a[i]) st.pop_back();
            L[i] = st.empty() ? 0 : st.back();
            st.push_back(i);
        }

        st.clear();

        // 右边第一个大于等于
        for(int i = n; i >= 1; i--)
        {
            while(!st.empty() && a[st.back()] <= a[i]) st.pop_back();
            R[i] = st.empty() ? n + 1 : st.back();
            st.push_back(i);
        }

        i64 ans = 0;
        for(int i = 1; i <= n; i++)
        {
            ans += 1LL * a[i] * (i - L[i]) * (R[i] - i);
        }
        return ans;
    }

## 八、从“按位置贡献”走向“按值贡献”

这一步是 `F. Sum of Fractions` 里真正更进一步的地方。

普通单调栈题通常做到：

- 每个位置的贡献次数算出来

就结束了。

但有些题并不关心：

- 这个极值出现在哪个位置

而更关心：

- 这个极值的数值是多少

例如：

- 最小值等于 `x` 的子数组有多少个？

这时候你还要继续做一步：

### 把位置贡献合并成值贡献

也就是：

1. 先算每个位置 `i` 的贡献次数
2. 再把同样数值的点贡献累加到一起

记成类似：

$$
cnt[x] = \text{最小值等于 } x \text{ 的子数组个数}
$$

这样后续你就可以按值做分类讨论、离线处理或者阈值扫描。

这一步在综合题里非常高频。

---

## 九、这和 `F. Sum of Fractions` 的关系

`F` 题最关键的一步，不是单调栈本身，而是：

### 先通过边际收益证明
对于一个子数组，所有操作最后都会给它的最小值对应的那个分数。

于是，子数组的最优值就变成：

- 基础部分：区间内所有数都贡献一点
- 额外部分：只和子数组最小值有关

一旦走到这一步，题目就自动转成：

- 统计每个子数组最小值是谁
- 统计每个最小值出现了多少次

然后单调栈自然就出来了。

所以 `F` 题真正值得学的是这一整条链：

1. 先研究单个对象的操作收益
2. 再比较边际收益
3. 发现最优只和极值有关
4. 再转成子数组极值贡献
5. 最后用单调栈做统计

这比只背一个单调栈模板有价值得多。

## 十、什么时候你应该立刻想到“子数组极值贡献”

以后做题时，只要看到下面这些信号，就要警觉：

### 1. 每个子数组的答案只和它的最小值 / 最大值有关
这是最直接的信号。

### 2. 原问题看起来是区间枚举，但区间内部真正有用的信息只有一个极值
例如：

- 最小值
- 最大值
- 次小值（有时也可以继续扩）

### 3. 你已经证明最优决策会落在极值元素上
这在很多综合题里会出现，像 `F` 题就是这样。

---

## 十一、和离线处理的关系

很多时候，单调栈只是前半步。

后半步还会出现：

- 按值排序
- 双指针离线
- 阈值分类
- 前缀和维护

这是因为极值贡献通常只是帮你把：

- “按位置问题”

转成了：

- “按值问题”

一旦变成按值问题，后面就经常会接：

- 扫描线
- 离线
- 前缀和
- 数据结构

所以你要记住：

> 单调栈常常不是终点，而是中间桥梁。

---

## 十二、这类题最常见的误区

### 1. 只会背公式，不知道公式怎么来的
一旦比较号变一下、题意稍微变一下，就不会用了。

### 2. 严格 / 非严格边界乱写
这是最高频 bug。

### 3. 只会按位置算贡献，不会继续按值合并
在综合题里，这一步很重要。

### 4. 看到单调栈就硬上
有些题并没有证明答案只和极值有关，这时候单调栈就不是正路。

---

## 十三、做题时的推荐思考顺序

如果你以后碰到类似题，建议按这个顺序想：

### 第一步
问自己：

- 子数组答案到底和什么有关？
- 是不是只和最小值 / 最大值有关？

### 第二步
如果是，只需要统计：

- 每个位置作为极值时能负责多少个子数组

### 第三步
立刻想到单调栈找左右边界：

- 左边能扩多远
- 右边能扩多远

### 第四步
如果题目后续按值分类，再把位置贡献合并成值贡献。

这就是一个完整套路。

---

## 十四、你真正该记住的不是模板，而是这条思维链

最后我把这份笔记压成一句最核心的话：

> **一旦你证明“子数组答案只和某个极值有关”，  
> 就应该把问题转成“每个位置作为极值时能贡献多少个子数组”，  
> 然后用单调栈统计左右边界。**

这才是“子数组极值贡献 + 单调栈”真正值得沉淀的部分。

---

## 十五、小结

这份笔记真正想让你带走的是三件事：

### 1. 公式来源
不是死记：

$$
(i - L[i]) \times (R[i] - i)
$$

而是理解左右端点为什么这样乘。

### 2. 边界选择
一边严格、一边非严格，避免重复统计。

### 3. 更高层的用途
单调栈不只是窗口最值工具，它更是：

- 从“区间问题”
- 到“位置贡献”
- 再到“按值统计”

的一座桥。

如果你把这三点真正理解了，那么以后再看到类似 `F. Sum of Fractions` 这样的题，你就不会只停留在“这题好像可以单调栈”，而是能顺着整条逻辑链把它拆开。
