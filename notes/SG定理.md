# SG定理

## 一、这是什么

SG 定理是用来解决一类经典博弈问题的工具，尤其适用于：

- 两个人轮流操作
- 双方都能看到完整状态
- 没有随机性
- 不能操作的人输
- 多个子游戏可以拼成一个大游戏

这类游戏通常被称为 **公平组合游戏**。

常见例子有：

- Nim 游戏
- 取石子游戏
- 减法游戏
- 可以拆成若干独立部分的图上博弈

如果你以后在题目里看到：

- “两个人轮流操作”
- “每次可以从若干合法转移里选一个”
- “无法操作者输”
- “多个部分互不影响，可以任选一个部分操作”

那么就应该立刻想到：

> 这题会不会是 SG 定理？

---

## 二、先理解什么是公平组合游戏

SG 定理不是对所有博弈都能用，它有适用范围。

### 1. 公平

公平的意思是：

- 当前轮到谁操作，双方可选的合法操作完全一样
- 不能因为当前是先手还是后手，就拥有不同的操作集合

也就是说，规则只和“状态”有关，不和“是谁在操作”有关。

### 2. 组合

组合的意思是：

- 整个游戏由若干个互相独立的小游戏组成
- 每次操作时，你可以只在其中一个小游戏上动一步
- 其他小游戏保持不变

例如：

- 有几堆石子，每次从其中一堆里操作
- 有若干个棋子，每次只移动其中一个
- 有多个独立图状态，每次只选其中一个图走一步

### 3. 正常局面（Normal Play）

SG 定理默认的输赢规则是：

- **不能操作的人输**

这个条件非常重要。

如果题目是“不能操作的人赢”，那就是另一类博弈，不能直接套 SG 定理。

---

## 三、什么是 SG 函数

这是整套理论的核心。

设一个状态为 `x`，从 `x` 可以一步走到很多后继状态：

- `y1`
- `y2`
- `y3`
- ...

那么定义：

$$
SG(x) = mex(\{SG(y_1), SG(y_2), SG(y_3), \dots\})
$$

其中 `mex` 表示：

> 在一个非负整数集合中，最小的没有出现过的非负整数

例如：

- `mex({1, 2, 4}) = 0`
- `mex({0, 1, 3}) = 2`
- `mex({0, 1, 2}) = 3`

---

## 四、为什么要这样定义

很多同学第一次看到 `mex` 会觉得很神秘，甚至像“公式硬记”。

其实它背后的意思并不神秘。

你可以把 `SG(x)` 理解为：

> 这个状态 `x` 的“等价 Nim 堆大小”

也就是说，一个复杂游戏状态，最后都可以被压缩成某个 Nim 游戏中的一堆石子数。

而 `mex` 的作用，是保证：

- 如果一个状态能走到某些 SG 值
- 那么它自己的 SG 值一定不能和这些后继相同
- 它取最小没出现过的那个值

这样就能保证整个状态系统满足标准博弈的递推关系。

你不一定一开始就要完全理解它的抽象意义，但至少要记住：

> `SG(x)` 是由所有后继状态的 SG 值决定的。  
> 算法上就是：先求后继，再取 mex。

---

## 五、SG 定理本身说了什么

如果一个组合游戏由若干个独立子游戏组成，它们的起始状态分别是：

- `s1`
- `s2`
- `s3`
- ...
- `sn`

那么整局游戏的胜负，只看：

$$
SG(s_1) \oplus SG(s_2) \oplus \cdots \oplus SG(s_n)
$$

其中 `\oplus` 表示按位异或。

### 结论

- 如果异或和等于 `0`，那么当前局面是 **必败态**
- 如果异或和不等于 `0`，那么当前局面是 **必胜态**

这就是 SG 定理最常用的结论。

以后做题时，很多时候你根本不需要证明太多，只要你能确认：

1. 这是公平组合游戏
2. 每个子游戏独立
3. 可以求出每个子游戏的 SG 值

那么最后一步几乎总是：

- 计算所有 SG 值的异或和
- 判断是否为 `0`

---

## 六、最重要的理解：为什么最后是异或

因为 Nim 游戏是这一类博弈的“标准模型”。

而 SG 理论的本质，就是：

> 任何公平组合游戏状态，都等价于某个 Nim 堆大小

于是：

- 一个子游戏状态等价于一个 Nim 堆
- 多个子游戏的组合，就等价于多个 Nim 堆的组合

而 Nim 的结论就是：

- 异或和为 `0` 时必败
- 异或和不为 `0` 时必胜

所以 SG 定理最后自然落到了“异或”上。

你可以这样记：

- `mex` 用来把状态变成 Nim 堆大小
- `xor` 用来合并多个 Nim 堆

这两个步骤合在一起，就是整套 SG 理论的使用方式。

---

## 七、怎么判断一道题能不能用 SG 定理

这是实战里最关键的问题。

你做题时，可以按下面顺序问自己。

### 1. 是不是两人轮流操作

如果不是，SG 基本就没法直接用。

### 2. 操作是否合法只和当前状态有关

如果不同玩家有不同操作，那么不是公平游戏。

### 3. 不能操作的人是不是输

如果不是正常玩法，也不能直接套。

### 4. 多个部分是不是相互独立

如果每次只能操作一个子游戏，而且一个子游戏的变化不会影响别的子游戏，就很像组合游戏。

### 5. 单个状态能否枚举所有后继

如果能，那么就可以尝试用记忆化搜索 / 递推求 SG。

---

## 八、最基础的 SG 求法

最朴素的写法是记忆化搜索。

```/dev/null/sg.cpp#L1-20
vector<int> f;

int sg(int x)
{
    if(f[x] != -1) return f[x];

    set<int> s;
    for(auto y : nxt[x])
    {
        s.insert(sg(y));
    }

    for(int i = 0; ; i++)
    {
        if(!s.count(i))
        {
            return f[x] = i;
        }
    }
}
```

这里的含义是：

- `nxt[x]` 存状态 `x` 的所有后继状态
- 先递归求出所有后继的 SG 值
- 然后取 `mex`

这就是最标准的 SG 计算模板。

---

## 九、一个更贴近做题的模板

如果状态是整数 `x`，并且操作方式是“从 `x` 可以走到若干更小状态”，那常见写法如下：

```/dev/null/sg.cpp#L1-22
vector<int> f;

int sg(int x)
{
    if(f[x] != -1) return f[x];

    set<int> s;
    for(int y = 1; y <= x; y++)
    {
        if(check(x, y))
        {
            s.insert(sg(x - y));
        }
    }

    for(int i = 0; ; i++)
    {
        if(!s.count(i))
        {
            return f[x] = i;
        }
    }
}
```

其中：

- `check(x, y)` 表示这一步操作是否合法
- `x - y` 只是举例，实际后继可以按题意改

## 十、例子：按 gcd 条件取石子

这是旧草稿里的例子，我们把它讲清楚。

### 题意模型

有 `n` 堆石子，第 `i` 堆有 `a[i]` 个石子。

两个人轮流操作，每次可以任选一堆，拿走若干石子。  
如果当前选的是一堆大小为 `x` 的石子，那么你拿走的数量 `y` 必须满足：

$$
gcd(x, y) = 1
$$

问先手是否必胜。

---

## 十一、为什么这题可以用 SG 定理

因为它满足 SG 的几个关键条件。

### 1. 两人轮流操作

满足。

### 2. 操作规则对双方完全一样

满足。

### 3. 不能操作的人输

满足正常玩法。

### 4. 每一堆石子彼此独立

每次只会操作一堆，其他堆不受影响。

这就说明：

- 每一堆石子都是一个独立子游戏
- 整个游戏是这些子游戏的组合

因此完全可以使用 SG 定理。

---

## 十二、这题怎么求单堆的 SG 值

设 `sg(x)` 表示：

- 一堆大小为 `x` 的石子对应的 SG 值

从状态 `x` 可以转移到哪些状态？

如果拿走 `y` 个石子，那么剩下的是：

$$
x - y
$$

但不是所有 `y` 都行，必须满足：

$$
gcd(x, y) = 1
$$

所以递推就是：

- 枚举所有合法的 `y`
- 把 `sg(x - y)` 放进集合
- 最后取 mex

模板可以写成：

```/dev/null/sg.cpp#L1-22
vector<int> f;

int sg(int x)
{
    if(f[x] != -1) return f[x];

    set<int> s;
    for(int y = 1; y <= x; y++)
    {
        if(gcd(x, y) == 1)
        {
            s.insert(sg(x - y));
        }
    }

    for(int i = 0; ; i++)
    {
        if(!s.count(i))
        {
            return f[x] = i;
        }
    }
}
```

然后总游戏的结果就是：

```/dev/null/sg.cpp#L1-10
int xorsum = 0;
for(int i = 1; i <= n; i++)
{
    xorsum ^= sg(a[i]);
}

if(xorsum == 0) cout << "Bob\n";
else cout << "Alice\n";
```

## 十三、SG 题最常见的做题流程

以后你做这类题，可以按这个流程来。

### 第一步：判断是不是公平组合游戏

这是入口。如果这一步都不满足，就别往 SG 上想。

### 第二步：定义单个状态的 SG 值

设：

- `sg(x)` 表示状态 `x` 的 SG 值

### 第三步：枚举状态 `x` 的所有后继

这一点非常关键。  
很多题的难点其实不是 SG 理论本身，而是你怎么高效找出所有后继。

### 第四步：收集所有后继的 SG 值，取 mex

这是核心递推。

### 第五步：如果有多个独立子游戏，就异或起来

最后判断异或和是否为 `0`。

---

## 十四、常见题型

SG 定理常见于下面这些题。

### 1. 取石子类

- 每次可以取若干个石子
- 取法可能有额外限制
- 多堆石子相互独立

这是最经典的 SG 模型。

### 2. 图上博弈

- 当前状态是图上某个点
- 每次沿边走到后继点
- 无法继续走的人输

这类题如果是 DAG，往往特别适合 SG。

### 3. 拆分游戏

- 一个数或一个区间可以拆成若干部分
- 后续在这些部分上继续玩

这类题常见于“把一个状态拆成多个子状态”的博弈题。

### 4. 带限制的减法游戏

- 每次减去一个来自某集合的值
- 或必须满足某个数论条件

这类非常适合直接写 `sg(x)`。

---

## 十五、做 SG 题时的难点通常不在定义，而在这三点

### 1. 你有没有正确判断“它是不是组合游戏”

很多人一看到博弈就想 SG，但不是所有博弈都能用。

### 2. 你能不能正确枚举后继状态

这是最实战的难点。  
理论谁都知道要 `mex`，但很多题后继并不好枚举。

### 3. 你能不能发现状态之间的规律

有些 SG 题如果直接暴力求会很慢，需要找周期、找规律、找打表现象。

所以你要记住：

> SG 定理提供的是“判断框架”，  
> 真正的做题难点通常在“状态建模”和“后继转移”。

---

## 十六、常见易错点

### 1. 把“不公平游戏”也硬套 SG

如果双方操作集合不同，就不能直接用。

### 2. 忘记这是“不能操作者输”的规则

如果题目规则变了，结论也会变。

### 3. 多个子游戏之间其实不独立

如果操作一个部分会影响另一个部分，就不能简单异或。

### 4. 只会背公式，不会定义状态

SG 题最重要的不是记住：

$$
SG(x) = mex(\cdots)
$$

而是你要知道：

- 状态是什么
- 后继是什么
- 为什么多个状态可以异或

### 5. `mex` 写错

`mex` 不是最大值加一，也不是最小值。  
它是“最小没出现过的非负整数”。

---

## 十七、你可以这样记住 SG 定理

如果让我把它压缩成最核心的三句话，那就是：

### 第一句
单个状态的 SG 值，等于所有后继 SG 值集合的 `mex`。

### 第二句
多个独立子游戏的组合，整体 SG 值等于它们的异或和。

### 第三句
异或和为 `0` 是必败态，不为 `0` 是必胜态。

这三句就是做题时最常用的部分。

---

## 十八、总结

SG 定理本质上是在做一件事：

> 把复杂博弈状态，翻译成 Nim 游戏里的堆大小。

它最适合的题型是：

- 公平
- 轮流
- 正常玩法
- 可拆成若干独立子游戏

做题时的标准流程是：

1. 判断能否用 SG
2. 定义单状态
3. 枚举后继
4. 取 mex
5. 多状态异或

如果你以后遇到“多堆石子”“多个独立状态”“轮流操作”的题，先别急着乱想，先问自己一句：

> 这题会不会是公平组合游戏？  
> 如果是，那我能不能定义 SG 值？

这就是 SG 题真正的入口。
