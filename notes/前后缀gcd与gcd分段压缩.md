# 前后缀 gcd 与 gcd 分段压缩

## 前言

这一份笔记想讲清楚一个在竞赛里非常实用、但很多人第一次见会觉得有点“神奇”的套路：

- **前后缀 gcd**
- **gcd 分段压缩**

它们经常一起出现，尤其是在下面这种题里：

- 要枚举区间右端点或左端点
- 要考虑删掉 / 替换 / 拼接一段区间
- 区间信息里出现 `gcd`
- 但你又不能真的枚举所有区间

如果你只是记一句“区间 gcd 只有 `O(log V)` 种”，那做题时还是很容易不会用。  
所以这份笔记会重点讲三件事：

1. 为什么区间 gcd 只会变化很少次  
2. 前后缀 gcd 为什么这么常见  
3. gcd 分段压缩到底怎么写、怎么用  

---

## 一、先从 gcd 的一个基本性质开始

我们先记住一个非常重要的事实：

> 当你不断往一个集合里加入新数字时，整个集合的 gcd 只会：
>
> - 保持不变
> - 或变小
>
> 而且它每次变小后，一定会变成原来的一个因子。

例如：

```/dev/null/example.txt#L1-6
gcd(12) = 12
gcd(12, 18) = 6
gcd(12, 18, 30) = 6
gcd(12, 18, 30, 9) = 3
gcd(12, 18, 30, 9, 21) = 3
gcd(12, 18, 30, 9, 21, 10) = 1
```

你会发现：

- gcd 不会上下乱跳
- 它只会一路下降
- 而且下降次数其实不多

这就是后面“分段压缩”的根本原因。

---

## 二、为什么区间 gcd 的种类不会很多

这个结论非常关键：

> 对固定右端点 `r`，所有区间 `[l, r]` 的 gcd 值，只有 `O(log V)` 种。  
> 这里 `V` 是数值上界。

很多同学第一次看到会问：

- 明明左端点 `l` 有 `n` 种
- 为什么 gcd 只有 `O(log V)` 种？

### 原因

假设你固定右端点 `r`，然后让左端点不断往左扩：

- `[r, r]`
- `[r-1, r]`
- `[r-2, r]`
- ...

随着区间越来越长，gcd 只会不断变小。  
而一旦变小，它至少会“有效下降一截”。

更准确地说：

- 新 gcd 一定是旧 gcd 的因子
- 如果新 gcd 和旧 gcd 不相等，那么新 gcd 至少不超过旧 gcd 的一半（不严格总是除 2，但数量级上变化次数很少）

所以一个数从 `V` 一路降到 `1`，不可能变化太多次。  
这就说明：

- 虽然区间很多
- 但不同的 gcd 值不多

这就是所谓的：

- **gcd 分段**
- **gcd 压缩**

---

## 三、什么叫 gcd 分段压缩

我们先说直观版。

对于固定右端点 `r`，你去看所有区间 `[l, r]` 的 gcd。  
你会发现，随着 `l` 从 `r` 往左移动，gcd 值会形成一段一段相同的结构。

例如可能出现：

```/dev/null/example.txt#L1-6
[l, r] 的 gcd:
l = r         -> 60
l = r-1       -> 20
l = r-2       -> 20
l = r-3       -> 10
l = r-4       -> 10
l = r-5       -> 10
l = r-6       -> 5
```

那么我们就没必要把每个 `l` 都单独记下来。  
只需要压成：

```/dev/null/example.txt#L1-4
(60, 1个位置)
(20, 2个位置)
(10, 3个位置)
(5, 1个位置)
```

或者更常见地，记成：

- 某个 gcd 值
- 这个 gcd 最右能覆盖到哪个左端点位置

这就是 gcd 分段压缩。

---

## 四、最常见的压缩方式

比赛里最常见的是这样维护一个数组（或 vector）：

- `seg[i][0]`：某一段的 gcd 值
- `seg[i][1]`：这一段对应的位置边界

例如在枚举右端点 `r` 时，维护所有 `[l, r]` 的 gcd 信息：

```/dev/null/example.txt#L1-5
{gcd1, pos1}
{gcd2, pos2}
{gcd3, pos3}
...
```

这里的含义可以按你的实现来定，常见有两种：

### 写法 A
表示：

- 从某个左端点开始到某个位置为止，这段区间 gcd 都相同

### 写法 B
表示：

- 枚举到当前位置时，不同 gcd 值最后出现在哪个左端点

两种都行，只要你自己在转移时保持一致。

---

## 五、怎么从右端点 `r-1` 的压缩结果，更新到右端点 `r`

这是整个套路的核心。

假设你已经维护了：

- 所有区间 `[l, r-1]` 的 gcd 分段结果

现在加入新元素 `a[r]`，要更新成：

- 所有区间 `[l, r]` 的 gcd 分段结果

### 转移方式

原来每个 gcd 值 `g`，现在都会变成：

```/dev/null/example.txt#L1-1
gcd(g, a[r])
```

另外，还要新增一个新区间：

```/dev/null/example.txt#L1-1
[r, r]
```

它的 gcd 就是：

```/dev/null/example.txt#L1-1
a[r]
```

于是做法就是：

1. 把旧的每个 gcd 和 `a[r]` 重新取 gcd
2. 再插入新区间 `a[r]`
3. 把相同 gcd 的项合并掉

### 伪代码

```/dev/null/example.cpp#L1-22
vector<pair<int,int>> seg; // 旧状态
vector<pair<int,int>> nxt; // 新状态

nxt.clear();
nxt.push_back({a[r], r});

for(auto [g, pos] : seg)
{
    int ng = gcd(g, a[r]);
    if(nxt.back().first == ng)
    {
        // gcd 相同，合并
        nxt.back().second = pos;
    }
    else
    {
        nxt.push_back({ng, pos});
    }
}
seg = nxt;
```

注意，不同实现里：

- `pos` 表示左端点边界
- 或某段最远位置

这个会略有区别，但核心思想不变：

> 把旧 gcd 和新数做 gcd，再把相同项合并。

---

## 六、为什么合并之后数量仍然很少

因为 gcd 变化次数本来就少。

每次更新时：

- 旧的若干 gcd 值经过一次 `gcd(g, a[r])`
- 新生成的结果只会更少，不会更乱
- 相同 gcd 会被立刻合并

所以整个结构的长度始终维持在：

- `O(log V)`

这就是为什么这个做法总复杂度通常能做到：

- `O(n log V)`
- 或 `O(n log^2 V)` 附近

远好于枚举所有区间。

---

## 七、前后缀 gcd 是什么，为什么常和这个套路一起出现

前后缀 gcd 是另外一个非常实用的工具。

### 定义

设数组为 `a[0..n-1]`。

那么：

- `pre[i]` 表示前 `i` 个数的 gcd
- `suf[i]` 表示从 `i` 到结尾的 gcd

例如：

```/dev/null/example.cpp#L1-12
vector<int> pre(n + 1), suf(n + 1);

for(int i = 0; i < n; i++)
{
    pre[i + 1] = gcd(pre[i], a[i]);
}

for(int i = n - 1; i >= 0; i--)
{
    suf[i] = gcd(suf[i + 1], a[i]);
}
```

### 它的用途

前后缀 gcd 常用来表示：

- 去掉一段区间后的 gcd
- 把一段区间替换成别的内容后的整体 gcd
- 左边一部分 + 中间一部分 + 右边一部分拼起来的 gcd

例如：

如果你删掉区间 `[l, r]`，那么剩下部分的 gcd 就是：

```/dev/null/example.txt#L1-1
gcd(pre[l], suf[r + 1])
```

这个式子特别常见。

---

## 八、为什么这两个套路经常一起出现

因为很多题目都会长这样：

- 枚举一个区间右端点 `r`
- 然后中间某一段的 gcd 需要动态变化
- 左边或右边的部分想快速得到 gcd
- 最后把几段拼起来算答案

这时候你会自然需要：

### 1. 前后缀 gcd
快速得到“区间外”的 gcd

### 2. gcd 分段压缩
快速得到“区间内所有可能的 gcd 状态”

然后把它们合起来。

---

## 九、一个典型应用模型

这类题最常见的结构是：

> 枚举右端点 `r`，再枚举区间左端点 `l`，  
> 但 `[l, r]` 的 gcd 不能暴力枚举，  
> 于是用 gcd 分段压缩。

同时题目里又可能有：

- 区间左边 `[0, l-1]`
- 区间右边 `[r+1, n-1]`

它们的 gcd 可以用前后缀 gcd 立刻算出。

### 最终答案的样子可能会是

```/dev/null/example.txt#L1-1
gcd(左边部分, 中间部分, 右边部分)
```

而：

- 左边部分靠 `pre`
- 右边部分靠 `suf`
- 中间部分靠 gcd 分段压缩

这就是这两个套路为什么经常打包出现。

---

## 十、这类题的代表性思维

以后你看到下面这些信号时，就该想到这套东西：

### 信号 1：区间信息是 gcd
只要区间信息是 gcd，就要立刻想到：

- gcd 不会变化很多次
- 很可能能分段压缩

### 信号 2：要枚举右端点 / 左端点
如果题目是：

- 枚举 `r`
- 再处理所有 `[l, r]`

那 gcd 分段压缩特别常见。

### 信号 3：区间外的部分也要参与答案
这时候前后缀 gcd 经常能立刻接上。

---

## 十一、这类题最容易错的地方

### 1. 不理解“为什么 gcd 只有很少种”
如果只是死记模板，一旦题目变形就不会用了。

### 2. 合并相同 gcd 时边界写错
这是最常见 bug。

### 3. 前后缀下标写错
比如：

- `pre[i]`
- `pre[i+1]`
- `suf[i]`
- `suf[r+1]`

这类非常容易偏一位。

### 4. 忘记新区间 `[r, r]`
每次加入新元素时，别忘了它自己单独形成的新 gcd 状态。

---

## 十二、一个推荐的理解顺序

如果你第一次真正学这个套路，建议按下面顺序理解：

### 第一步
先理解前后缀 gcd。

因为这个最直观，也最容易掌握。

### 第二步
再理解固定右端点时，`[l, r]` 的 gcd 为什么只有很少种。

### 第三步
再去看 gcd 分段压缩的更新过程：
- 旧状态怎么转移
- 新区间怎么加入
- 相同 gcd 怎么合并

### 第四步
最后再去理解这两个套路怎么组合到一道题里。

这样会比一开始直接背整套代码更稳。

---

## 十三、这份笔记最值得你带走的三句话

### 第一句
固定一个右端点时，所有 `[l, r]` 的 gcd 值只有 `O(log V)` 种。

### 第二句
前后缀 gcd 可以非常快地表示“区间外”的 gcd。

### 第三句
很多 gcd 题的本质，就是：
- 区间内用 gcd 分段压缩
- 区间外用前后缀 gcd
- 最后把几部分拼起来

如果你把这三句话记住，这类题以后就会好认很多。

---

## 十四、和 `Round 972 D. Alter the GCD` 的关系

那道题里最值得提炼的，不是题目本身，而是它背后的模型：

- 左边部分 gcd
- 中间部分 gcd
- 右边部分 gcd
- 需要枚举很多区间
- 不能暴力做

所以自然就会用到：

- `pre_a / pre_b`
- `suf_a / suf_b`
- 以及对右端点枚举时的 gcd 分段压缩

这题是这两个套路一起出现的一个很典型的例子。

---

## 十五、最后总结

“前后缀 gcd + gcd 分段压缩”这套东西，本质上是在利用 gcd 的两个特点：

1. **可结合**
   - 可以把几段 gcd 再 `gcd` 起来

2. **变化次数少**
   - 固定一端时，不同 gcd 值不会很多

所以这类题真正的套路可以总结成一句话：

> **区间外靠前后缀 gcd，区间内靠 gcd 分段压缩。**

如果你以后做题时，看到：

- 区间
- gcd
- 枚举一端
- 拼接左右部分

这些关键词一起出现，就应该立刻想到这份笔记里的套路。
