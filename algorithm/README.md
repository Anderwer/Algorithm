# Algorithm 模板目录说明

## 目录定位

这个目录用于存放 **可以直接复制到比赛代码里使用的算法模板**。  
这里的文件目标是：

- 结构清晰
- 接口统一
- 尽量独立，不依赖题目特定变量
- 能直接拿去改
- 适合长期维护和上传到 GitHub

如果某个内容更偏“知识点讲解”“专题总结”“课堂笔记”，就不应该继续放在这里，而应该放到上层的 `notes/` 目录。

---

## 当前目录使用原则

### 1. `algorithm/` 放什么

这里放：

- 可直接复用的代码模板
- 结构完整的标准实现
- 常用数据结构 / 图论 / 数论 / 字符串模板
- 比赛里高频出现、适合直接复制修改的代码

例如：

- 树状数组
- 线段树
- 并查集
- LCA
- 最短路
- 拓扑排序
- Trie
- 字符串哈希
- 组合数
- 欧拉路
- 矩阵快速幂

### 2. `notes/` 放什么

不放在这里，改放 `Algorithm/notes/` 的内容包括：

- 专题讲义
- 知识点总结
- 公式推导
- 题解式笔记
- 比较零散的学习记录
- 更适合阅读而不是直接复制的材料

例如：

- 图论笔记
- 数论专题
- DP 专题
- 树的相关知识
- SG 定理
- 线性 DP 笔记

## 本轮整理后的“保留 / 合并”决策

这次整理的目标，不是把所有相似内容都删掉，而是区分：

- **重复且低质量的草稿**：删除
- **相似但代表不同做法**：保留，并明确职责
- **偏讲义内容**：迁移到 `notes/`

- 不要求“直接复制进比赛代码即可用”

### 3. 保留但明确区分的内容

有些文件主题相近，但其实代表的是 **不同做法**，不应该简单合并成一个文件。

#### `LCA-HLD.cpp` 和 `LCA-RMQ.cpp`

这两个文件都保留。

- `LCA-HLD.cpp`
  - 当前主推版本
  - 基于重链剖分求 LCA
  - 接口更统一，适合作为常用模板

- `LCA-RMQ.cpp`
  - 备选版本
  - 基于 Euler 序 + RMQ 求 LCA
  - 适合静态多次查询、希望做到 `O(1)` 查询时使用

为什么不合并成一个文件？

因为这两种方法虽然都在求 LCA，但：

- 预处理方式不同
- 查询复杂度不同
- 适用场景不同
- 写法风格也不同

强行揉在一个文件里，反而会让模板更臃肿、更不利于比赛时直接使用。

#### `FFT.cpp` 和 `NTT.cpp`

这两个文件也都保留。

- `FFT.cpp`
  - 复数 FFT
  - 适合实数卷积、整数卷积、大整数乘法等场景

- `NTT.cpp`
  - 数论变换
  - 适合模意义卷积

它们解决的问题很接近，但使用前提不同，不能互相替代，所以保留两份是合理的。

### 4. 已合并 / 精简的内容

以下文件在本轮中做了明显的“去草稿化”和“去重复化”处理：

- `快速幂.cpp`

- `并查集.cpp`
- `组合数.cpp`
- `欧拉路.cpp`
- `二分图.cpp`

这些文件原来普遍存在以下问题之一：

- 多个同名结构体混在一起
- 教学草稿、题目代码、模板代码混杂

- 可以直接复制
- 文件职责明确
- 注释偏简洁实用
- 更适合长期维护

## 2. `SegmentTree.cpp`

线段树模板集合。

- `SegmentTreeSumAdd`
  - 区间加 + 区间求和

适合解决：

- 区间维护

说明：

- 当前文件保留的是最常用、最实战的版本

# 八、这个目录后续怎么维护

为了让仓库长期保持整洁，建议以后遵循以下规则。

## 1. 模板文件只放“能直接抄”的内容

如果某个文件更像：

- 学习笔记
- 专题讲解
- 题解总结
- 零散草稿

那就不要放进 `algorithm/`，而应放到 `notes/`。

## 2. 一个文件尽量只承担一个明确主题

例如：

- 最短路模板集合
- 线段树模板集合
- Trie 模板集合

而不要出现：

- 多个同名结构体混在一起
- 教学草稿 + 主函数 + 模板同时出现
- 题目特定代码掺进通用模板

## 3. 命名尽量统一

建议优先使用：

- 清晰的结构体名
- 统一的 `init / add / build / query / modify / work` 接口风格
- 统一的头文件和说明风格

## 4. 讲解放到笔记里，模板保持克制

模板不是讲义。  
模板文件里只需要保留：

- 用途
- 适用范围
- 接口说明
- 少量使用示例

长篇解释更适合写到 `notes/` 目录。

## 5. 相似算法可以共存，但要明确职责

例如：

- `LCA-HLD.cpp` 与 `LCA-RMQ.cpp`
- `FFT.cpp` 与 `NTT.cpp`

这类文件不是简单重复，而是：

- 做法不同
- 适用场景不同
- 各自有存在价值

所以允许共存，但命名和 README 中必须解释清楚。

- `algorithm/`：放模板
